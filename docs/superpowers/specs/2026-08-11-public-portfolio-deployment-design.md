# AI 导购作品集公网发布设计

## 1. 目标

把当前本地作品集发布为一套可直接分享的公网体验：读者先进入产品案例页，理解产品问题、PRD、设计与评测，再一键进入可交互 Demo。案例页、Demo、API 和公开源码之间必须互相可达，并继续清楚标识“合成数据、概念原型、模拟加购”。

## 2. 已比较的方案

### 方案 A：Vercel 前端 + Railway API + GitHub 公开仓库（采用）

- Vercel 承载 Next.js Demo 与静态案例页；
- Railway 以单 worker 运行 FastAPI；
- GitHub 保存代码与部署配置，作为作品集的可核验源；
- 案例页在公网环境跳转到同站 Demo，本地 `file://` 仍跳转到 `127.0.0.1:3000`。

优点是适配当前技术栈，前后端职责清楚，案例页与 Demo 可使用同一前端域名。代价是需要维护两个云服务，并处理精确 CORS。

### 方案 B：前后端全部放 Railway（不采用）

服务数量较少，但 Next.js 静态资源/CDN、预览与前端发布体验不如 Vercel 直接；也没有必要为作品集把既有前端部署能力降级。

### 方案 C：只发布静态案例页，Demo 继续本地（不采用）

最简单，但“一键进入 Demo”对外部读者不成立，无法满足本次发布目标。

## 3. 公网信息架构

| 地址 | 角色 | 用户动作 |
|---|---|---|
| `https://<web-domain>/case-study` | 作品集主入口 | 阅读案例，打开关键证据，进入 Demo |
| `https://<web-domain>/` | 可交互 Demo | 浏览短视频、询问 AI、比较商品、模拟加购 |
| `https://<api-domain>/api/v1/health` | API 健康检查 | 仅用于部署与验收 |
| `https://github.com/teemoweng/ai-shopping-agent` | 公开源码 | 核验代码、文档与测试证据 |

案例页不复制维护第二份正文。构建脚本把权威 HTML、所需截图和六份原始证据文件确定性同步到 `apps/web/public/`，并用哈希 manifest 检查漂移。`/case-study` 由 Next.js rewrite 到静态 HTML。

## 4. 生产边界

### 4.1 API

- CORS 默认仍只允许本地两个开发源；生产通过 `ALLOWED_ORIGINS` 显式追加 HTTPS 前端域名；
- 禁止通配符、带凭证 URL、路径、查询和 fragment；
- Railway 使用一个 Uvicorn worker，关闭 access log，避免 operation identifier 出现在 URL 日志；
- 使用现有 `/api/v1/health` 作为部署健康检查；
- 会话与模拟交易仍是进程内状态：服务重启后会话丢失。这是作品集 Demo 的公开限制，不包装成生产架构。

### 4.2 Web

- `NEXT_PUBLIC_API_BASE_URL` 只在构建时注入公网 API `/api/v1`；
- 案例页的 Demo 链接按运行协议解析：`file://` 使用本地地址，`http(s)` 使用当前站点根路径；
- 案例页全部图片和原文阅读入口必须在公网同源可读，不依赖本机绝对路径；
- 不把 token、部署凭证、环境变量值或真实用户数据打包进 `public/`。

## 5. 失败与降级

- API 暂时不可用时，Demo 使用既有终态/冻结逻辑，不虚构成功；
- CORS 错配视为发布失败，不改成 `*` 规避；
- 云平台未登录时，代码和公开前验证可以继续，但 `TASKS.md` 保持 `IN PROGRESS`，不得声称已上线；
- 线上旅程不通过时保留部署供排查，但不把 URL当作最终交付。

## 6. 验收标准

1. GitHub 公开仓库可访问，且安全扫描没有未标注密钥、环境文件、原始健康信息或运行时交易标识；
2. Web 与 API 均为 HTTPS，健康检查返回 200；
3. 案例页 `/case-study` 的两处 Demo 入口均进入同站根路径；
4. 案例页六份全文证据、三张流程图和响应式布局可在公网读取；
5. 线上真实 API 旅程至少覆盖：打开导购、一次澄清、得到推荐、进入商品页、模拟加购；
6. 未授权 origin 的 CORS 预检失败，已配置前端 origin 成功；
7. 本地 API/Web 单测、构建、案例页验证与关键 E2E 全绿；
8. 发布报告记录 URL、source commit、平台、时间、测试结果、截图哈希和已知限制。

## 7. 当前明确限制

- 这是使用冻结合成商品与确定性 Workflow 的作品集原型，不是真实 TikTok Shop 产品；
- 没有真实 LLM、真实库存、真实支付、持久化数据库和用户账号；
- Railway 冷启动、免费额度和进程重启可能使会话失效；
- 本次上线证明“可公开体验与可复现”，不证明用户价值、推荐质量或转化提升。
