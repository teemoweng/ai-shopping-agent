# 离线关键证据文档阅读器设计

## 1. 背景与目标

产品案例页的“关键证据”目前只在居中 Modal Dialog 中展示摘要。读者可以理解每份证据的大意，但无法在不离开案例页的情况下阅读全文。

本次改造的目标是：读者点击任一证据卡后，可以在保持现有遮罩和弹窗视觉风格的前提下，阅读对应源文件的完整富文本内容；页面通过 `file://` 直接双击打开时也必须可用，不依赖本地服务器、网络请求或 CDN。

## 2. 已确认方案

采用“完整内容预渲染进单个 HTML”的 Document Reader Modal：

- 六份权威源文件在生成阶段转换为安全的富文本 HTML；
- 转换结果与文档目录一并嵌入 `vibe-coding-case-study.html`；
- 浏览器运行时只在已嵌入内容之间切换，不执行 `fetch()`；
- 每份文档保留源路径和内容哈希，支持检查嵌入内容是否落后于源文件；
- 弹窗保留当前视觉语言，但扩展为适合长文阅读的大尺寸文档阅读器。

### 权威源文件

1. `README.md`
2. `docs/superpowers/specs/2026-08-10-chat-first-lightweight-guide-design.md`
3. `artifacts/evidence/chat-first-verification.md`
4. `artifacts/evidence/chat-first-run-manifest.json`
5. `PLAN.md`
6. `TASKS.md`

当前六份文件合计约 105 KB。预渲染后仍适合嵌入单页，不需要拆分为远程文档服务。

## 3. 阅读体验

### 3.1 入口

- 证据卡保持现有 Hover / Focus 高亮反馈；
- 点击卡片打开原生 `<dialog>`；
- 卡片不再只映射到摘要，而是映射到一份完整文档。

### 3.2 桌面弹窗

- 最大宽度约 1000–1080 px；
- 最大高度约 `86dvh`；
- 顶部固定区域包含文档类型、标题、源路径、关闭按钮；
- 左侧为从二级、三级标题生成的目录；
- 右侧为独立滚动的完整富文本正文；
- 摘要作为正文开头的导读，不替代源文内容；
- 底部或顶部提供“查看原始文件”入口。

### 3.3 移动端弹窗

- 使用接近全屏的单栏 Document Reader Modal；
- 目录折叠为“本页目录”按钮；
- 正文使用单一纵向滚动区域；
- 关闭按钮始终可达，不出现横向页面溢出。

### 3.4 富文本规则

Markdown 阅读版至少支持：

- 标题与锚点；
- 段落、粗体、斜体和行内代码；
- 有序列表、无序列表和任务列表；
- 引用块；
- 表格；
- 代码块；
- 普通链接和仓库内相对链接。

Manifest JSON 使用结构化阅读视图展示全部字段，并保留可展开的格式化原文，不能只显示摘要或挑选部分字段。

## 4. 生成与同步

新增一个确定性生成脚本，职责限定为：

1. 读取六份源文件；
2. 计算 SHA-256；
3. 将 Markdown 或 JSON 转换为受控 HTML；
4. 生成目录和标题锚点；
5. 更新案例页内明确标记的 Evidence Templates 区域；
6. 提供 `--check` 模式，只检查源文件、哈希与嵌入内容是否一致，不修改文件。

生成器不得重写案例页其他内容。嵌入区域必须有稳定的开始和结束标记，避免覆盖人工维护的产品叙事与样式。

## 5. 安全与链接处理

- 源文件属于仓库内受信内容，但转换器仍默认转义原始 HTML；
- 不执行 Markdown 中的脚本、事件属性或内嵌 iframe；
- 仓库内相对链接按源文件所在目录解析，再重写为相对于案例页的链接；
- 外部链接使用新窗口打开并带 `rel="noreferrer"`；
- 原始文件入口只指向六份已声明的权威源文件。

## 6. 状态与失败处理

- 某份嵌入内容缺失时，卡片仍可打开弹窗，但显示明确的“文档尚未同步”状态和原始文件入口；
- 哈希不一致时，`--check` 必须非零退出，不能静默继续；
- 弹窗关闭后焦点返回原卡片；
- Escape、关闭按钮和点击遮罩均关闭弹窗；
- 切换目录锚点只滚动正文，不移动底层页面。

## 7. 验收标准

### 内容完整性

- 六份源文件均有对应阅读版；
- 每份文档的开头、正文中段和末尾哨兵文本均能在阅读器中找到；
- Manifest 的全部顶层字段和嵌套数据可访问；
- `--check` 在未改源文件时通过，任意源文件变化后失败。

### 交互与可访问性

- 在 `file://` 与 `http://127.0.0.1:4173` 两种入口均可打开六份完整文档；
- 桌面弹窗居中，移动端使用单栏长文模式；
- 目录、正文滚动、原始文件入口、Escape、遮罩关闭和焦点返回均可用；
- 键盘焦点不会进入遮罩后的页面；
- `prefers-reduced-motion` 下不依赖动画完成操作。

### 视觉

- 延续当前黑、白、红、青视觉系统；
- 弹窗更大但不变成 Drawer 或 Bottom Sheet；
- 长表格和代码块在正文内部横向滚动，不造成页面级横向溢出；
- 桌面与 390×844、320×700 视口均完成真实浏览器截图检查。

## 8. 不采用的方案

### 只增加“打开原文件”按钮

实现简单，但会把读者从案例页带到浏览器的原始 Markdown 文本，阅读体验割裂。

### 浏览器运行时 `fetch()` Markdown

可以始终读取最新源文件，但 `file://` 环境通常会受浏览器本地文件访问限制，无法满足已确认的离线要求。

### 为每份证据生成独立 HTML 页面

维护边界清楚，但会打断当前 Modal 阅读上下文，并增加六个独立页面的导航与样式维护成本。

## 9. 交付边界

本次只改产品案例页的证据阅读体验及其生成、检查工具，不修改 AI 导购 Demo、API、评测结果或源证据内容。

## 10. 实施状态

本设计已于 2026-08-11 实施完成：

- 六份权威源文件已预渲染进案例页，运行时不使用 `fetch()`、CDN 或远程 Markdown 服务；
- `pnpm build:case-study-evidence` 只更新标记内的 Evidence Templates，`pnpm check:case-study-evidence` 校验源文件哈希与嵌入内容；
- Node 单元测试覆盖受控 Markdown / JSON、转义、链接重写、完整内容与漂移检测；
- Playwright 已在 `file://` 和临时 HTTP 两种入口验证 6/6 全文，以及桌面、390×844、320×700 三种阅读布局；
- 最终命令、截图哈希和限制见 [案例页证据阅读器验证记录](../../../artifacts/evidence/case-study-evidence-reader-verification.md)。
