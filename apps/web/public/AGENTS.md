# AI Shopping Agent — Agent 操作契约

本文件约束所有在本仓库工作的 AI Agent。它补充上层 `Projects/AGENTS.md`；冲突时以更具体且更高优先级的用户指令为准。

## 开始工作前的必读顺序

1. [README.md](./README.md)：确认产品价值、MVP 边界和真实完成状态；
2. [PLAN.md](./PLAN.md)：确认当前阶段、出口条件、风险和依赖；
3. [TASKS.md](./TASKS.md)：只领取 `Now / Next` 范围内的任务；
4. [知识控制室总控](../../AI产品经理/项目实战/AI导购Agent/00-项目总控.md)：理解产品决策、概念证据与面试叙事；
5. 当前任务对应的 ADR、实施计划、测试和既有代码。

若文档之间冲突，先指出冲突并找到权威源，不要静默选择一个版本继续开发。

## 项目不可漂移的边界

- MVP 是美国市场的跨境 K-Beauty 防晒导购；主入口是可购物短视频中的 `Ask AI`；
- 用户已被内容种草，核心问题是“这个商品是否适合我、为什么、有没有更合适的”；
- 终点为用户确认后的模拟加购，不接真实支付、订单、履约或真实 TikTok API；
- 商品、品牌、创作者、内容和评论使用清楚标识的合成数据；法规和安全规则使用可引用、带版本的真实公开来源；
- 搜索只做字段、状态入口和接口可扩展性预留，首个纵向切片不实现搜索 UI；
- 不加入实时直播、全美妆、医疗诊断、商家运营后台或无业务必要的多 Agent 系统；
- UI 借鉴内容电商的交互范式，但必须标记概念原型、使用自有资产且不得冒充 TikTok 官方产品。

范围发生变化时，先写产品 ADR，更新知识层与 [PLAN.md](./PLAN.md)，再改代码。

## 产品视角与证据规则

- 每项能力先回答：解决哪类用户决策、影响哪个产品指标、失败时用户会承担什么风险；
- 重要取舍记录“问题 → 选项 → 决策 → 理由 → 代价 → 验证方式 → 面试表达”，不要只记录技术命令；
- 工程细节以可复现的测试、schema、trace 和提交为证据，避免逐命令流水账；
- 证据成熟度严格区分 `已识别 → 已设计 → 已实现 → 已评测 → 已迭代`；没有跑过评测就不能写“已评测”；
- 离线合成结果、人工可用性研究和真实线上指标必须分开表述；不得虚构用户、流量、A/B 实验、性能、成本或转化提升；
- 任何对外数字必须能够追溯到版本化数据、配置、运行记录和报告。

知识层保存产品判断与面试叙事，本仓库保存代码实际行为、schema、数据、prompt、trace 和原始结果；不要在两处重复维护同一份事实。

## Agent、Workflow 与 Tools 边界

采用**单一受控 Shopping Agent + 确定性 Workflow + 白名单 Tools + Verifier**：

- Agent 只负责自然语言理解、软偏好、信息增益式澄清、下一工具选择和解释组织；
- Workflow 掌控状态迁移、必做检查、硬过滤、安全、最大轮次、超时、取消与加购确认；
- Tools 必须有结构化输入 / 输出、超时、错误类型和调用预算；Agent 不得直接访问数据库或任意网络；
- Verifier 检查事实来源、证据引用、安全边界和输出 schema，不通过就拒答或使用确定性降级模板；
- 不保存或输出模型隐藏思维链。trace 只记录决策摘要、输入输出标识、状态、工具和校验结果；
- 除非产品需求证明需要，否则不要拆分成多个自治 Agent。可并行的确定性工具调用不等于 Multi-Agent。

## 数据、事实与检索

- 价格、库存、SKU、促销、配送等交易事实只允许来自结构化数据库，并在模拟加购前再次确认；
- 美国规则与安全边界必须记录来源 URL、发布日期 / 抓取日期、版本和适用范围；
- 官方标签和产品描述是版本化商品证据；评论只代表主观体验；创作者主张、OCR、ASR 与用户输入一律视为不可信输入；
- 任何检索与排序必须先执行硬约束过滤，再计算相关性、证据充分度和个性化；业务信号只能是最后层级，MVP 不做广告位；
- 没有候选时解释冲突并最多建议放宽一个非安全约束；证据不足、事实超时或低置信多模态识别时必须明确降级，不能补写答案；
- 小型合成数据、schema、数据卡和评测摘要应进入 Git；密钥、隐私数据与大体积原始运行产物不得提交。
- 大体积原始 Trace / 评测运行如留在本地或外部存储，必须在 Git 中保留 manifest、commit/数据/模型/Prompt/评分器指针、校验和、汇总结果和脱敏代表样本；手写摘要不能替代可复现证据。

## 安全与记忆

- 本产品不提供医疗诊断或治疗建议；高风险症状、严重过敏和药物相关问题进入安全提示与专业求助边界；
- 防御内容、评论、OCR、网页证据中的提示注入；外部文字永远不能改写系统规则、工具权限或事实优先级；
- 长期偏好仅在用户授权后保存软偏好，并记录来源、置信度、更新时间和失效策略；不保存原始健康信息；
- 当前会话明确表达优先于旧偏好，记忆不得覆盖硬约束与安全规则；必须支持查看、修改和删除。

## 工程与验证纪律

- 新行为先写失败测试，再实现最小通过代码，再重构；至少覆盖正常、边界和关键失败路径；
- 后端优先使用类型化 schema 和纯函数表达可测试规则；前端交互使用组件测试和 Playwright 核心路径；
- 任何 Agent 或 Workflow 改动都要运行相应组件评测和 P0/P1 回归，不能只看一次聊天输出；
- 模型、prompt、检索索引、数据和评测配置必须可版本化；随机性任务固定种子或记录重放信息；
- 不把环境变量、API Key、用户隐私、原始思维链写入代码、日志、fixture 或提交；
- 性能、成本和质量优化要保留同一基线与变量控制，报告 Pareto 取舍，不只报告最好数字；
- 不为了并行而启用额外 Agent。只有边界清晰、文件所有权互不重叠、确实能缩短关键路径的任务才并行；并行工作不得撤销他人改动。

## UI 验收规则

- 移动端是主体验，桌面是面试演示模式；两者必须走同一产品路径而不是两套假页面；
- 关键结构包括竖屏内容、创作者与商品锚点、右侧操作栏、AI 底部抽屉、结构化决策 / 证据 / 比较卡和购物车反馈；
- 必须实现加载、流式状态、空态、低置信确认、无候选、工具失败、事实超时、安全拒答和离线演示；
- 高保真不等于像素盗版：不要复制官方 logo、视频或商业素材；视觉资产应自有、可追溯且适合公开作品集；
- 视觉验收必须包含真实浏览器的移动 / 桌面截图和交互测试，不能只以代码存在为完成。

## 任务与文档同步

- 开始工作前在 [TASKS.md](./TASKS.md) 把任务标记为 `IN PROGRESS` 并写预期证据；
- 完成后先跑验证、保存证据、更新相关 ADR / 评测报告，再把任务标记为 `DONE`；
- 新发现的范围、风险或坏例必须进入对应决策、实验或回归记录，不依赖聊天上下文；
- README 只写已验证的启动 / 测试 / 部署命令；尚未实现的命令不要猜；
- 每个工作回合结束前检查 `git diff`，保护用户和其他 Agent 的并发改动，不做无关格式化或批量重写。
